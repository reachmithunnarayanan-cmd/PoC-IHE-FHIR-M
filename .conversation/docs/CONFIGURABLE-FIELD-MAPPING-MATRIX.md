# Configurable Field-Mapping Matrix and Sanitisation Workstation Rules

## 1. Purpose

This matrix connects the canonical field dictionary to the three PoC projections:

- PME (AFMSF 3A) to generated AME (AFMSF 3B).
- ADN to public-side FHIR-inspired XML.
- Public-side FHIR-inspired XML to ADN.

The Secure Data Exchange Workstation must let an authorised demo operator select or deselect fields for each transfer direction in a configuration panel. The selected fields form the transfer allowlist for that direction. The source record is never modified by deselection.

This is a configurable PoC demonstration, not an approved operational sanitisation policy. The initial settings below are illustrative defaults for synthetic data only.

## 2. Configuration panel behaviour

### 2.1 Layout

Provide two independent direction tabs:

1. **ADN → Public**
2. **Public → ADN**

Each tab contains:
- Search by field label or canonical ID.
- Expandable field groups: Identity, Service, Encounter, History, Observations, Investigations, System Examinations, Dental, Eye, ENT, Gynaecology, Immunisation, Documents, Authorities and Exchange Metadata.
- A checkbox for each configurable field: selected means include in this transfer; deselected means exclude.
- Group-level Select all / Deselect all controls, with a visible count of selected fields.
- A visible indication for fields that are locked, derived, conditionally available, or require review.
- A right-side summary of included, excluded, transformed, added/enriched, held and unavailable fields.
- A preview of the outgoing package field list and a before/after transformation report.

### 2.2 Selection semantics

- Selection is direction-specific. Selecting a field for ADN → Public does not select it for Public → ADN.
- Selected means eligible for inclusion, subject to validation and mandatory policy constraints.
- Deselected means omitted from the outgoing package. It does not delete, clear or alter the source value.
- A field not present in the source record remains unavailable; selecting it does not create a value.
- Fields marked conditional are included only when populated and when their condition is met.
- A field marked hold cannot be exported until the operator resolves the stated issue.
- A derived field is computed only under a documented deterministic rule and must carry derivation provenance.
- Selecting a parent group does not override a field-level restriction.
- Do not provide a global "select everything" action that can silently include restricted military identifiers. Group selection must still respect locked restrictions and show exceptions.

### 2.3 Locked and protected fields

The configuration UI must distinguish:
- **Operator-configurable:** can be selected/deselected for the direction.
- **Locked excluded:** cannot be enabled by an ordinary demo operator; the UI explains why.
- **Required exchange metadata:** generated by the workstation and always included in the package envelope, not selectable as clinical payload.
- **Conditional:** can be selected but only emitted if a valid source value exists.
- **Review required:** held until a human resolves ambiguity.

For this PoC, military identifiers and service-administration fields are locked excluded in ADN → Public by default. Do not implement an override that implies approval to release classified or operational data. A privileged-policy override is out of scope for this demo.

### 2.4 Save, apply and audit

- Configuration is a versioned transfer profile, not a change to the canonical source record.
- Show profile name, direction, version, last modified by and timestamp.
- Require an explicit **Apply profile** action before creating the outgoing package.
- At package creation, snapshot the effective configuration and mapping version into the transaction audit.
- Record per-field action and reason: pass, transform, add/enrich, remove, hold, unavailable or unsupported.
- Changing the configuration later must not retroactively alter previously generated packages or audit records.
- Provide a **Restore demo defaults** action with confirmation.
- Show a clear warning when a user deselects a field that the receiving form/profile expects. Do not silently insert a fabricated value.

## 3. Directional mapping matrix

Legend:
- **P** = pass / direct map.
- **T** = transform / map to another representation.
- **A** = add or enrich from an authorised workstation-side source.
- **R** = remove / exclude from outgoing package.
- **H** = hold for review.
- **C** = conditional; include only if present and permitted.
- **—** = not applicable to that projection.

The initial direction defaults are PoC demonstration settings, not production release policy.

## 4. PME-to-AME form projection rules

| AME output field group | PME source | Rule |
|---|---|---|
| Personal/service data | PME personal data | Direct map for equivalent fields. |
| Past history/category | PME personal data | Map while preserving effective-date and decision-context distinctions. |
| Last examination | PME last AME carried out at | Map location; do not invent a date/reference absent from source. |
| Dental | PME Dental | Map tooth chart and summary fields. |
| Physical capacity | PME Medicine | Direct map. |
| Cardiovascular | PME Medicine | Map findings; retain separate R/DMT and TMT source studies. |
| Respiratory/chest X-ray | PME Medicine | Map findings and report reference. |
| Gastrointestinal/CNS | PME Medicine | Direct map. |
| Laboratory | PME Medicine | Map common analytes; urea, creatinine and uric acid remain PME-only. |
| Surgery/locomotor | PME Surgery | Map common findings. |
| Gynaecology | PME Gynaecology | Map common fields where applicable. |
| Vision | PME Eye | Map common vision/CP; retain PME-specific specialist tests in source. |
| Hearing/ENT | PME ENT | Map common fields; retain extra detail. |
| Immunisation | No explicit PME section | AME-only; leave blank or request separate entry. |
| Final category | PME board fitness/category | Map only with decision context; do not conflate recommendation and approval. |
| Signatures/authorities | PME specialists and board | Map only to equivalent roles; never copy a signature into an unrelated authority field. |

Before AME generation, display a completion report: Ready; Ready with optional fields blank; or Requires completion of AME-required fields. Missing values are never fabricated.

## 5. XML projection contract

The PoC public-side package is FHIR-inspired representational XML, not validated FHIR or ABDM XML. Suggested sections include ClinicalExchangeBundle/BundleMetadata, Patient, Encounter, Condition, Observation, DiagnosticReport, Practitioner, Organization, DocumentReference and Provenance.

Canonical fields should map through a maintained table of canonical ID, XML section/path, datatype, transformation and eligibility. Unsupported or unmapped fields appear in the transformation report; do not silently discard them.

## 6. Transaction report

For each package, show:
- Direction and profile name/version.
- Source and destination.
- Input and output package IDs/hashes.
- Counts of selected, transferred, transformed, added, removed, held, unavailable and unsupported fields.
- Per-field canonical ID, source value presence, configured selection, applied action and reason.
- Operator, timestamp, mapping version and XML representation version.

Never show sensitive values in a public-side report if those values have been excluded from the package. The workstation's internal audit can retain references/hashes and the action without copying restricted values into the outbound report.

## 7. Acceptance criteria

1. The operator can independently configure field selection for each transfer direction.
2. Selection and deselection are visible at field and group level.
3. Locked exclusions cannot be enabled by an ordinary operator.
4. The outgoing package contains only selected, available and permitted fields plus required generated envelope metadata.
5. Deselecting a field never changes or deletes the source record.
6. The operator can preview the exact outgoing field list and transformation report before export.
7. Every transaction snapshots the effective profile and mapping version.
8. PME-to-AME generation uses the documented projection matrix and reports gaps.
9. Public XML remains clearly labelled representational and non-conformant for this PoC.
